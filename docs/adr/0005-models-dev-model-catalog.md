# ADR-0005. Каталог models.dev как источник характеристик моделей

- **Статус:** Accepted
- **Дата:** 2026-09-05
- **Затрагивает:**
  `desktop/src/host/infrastructure/text-generation/models-dev.catalog.ts`,
  `desktop/src/host/infrastructure/text-generation/provider-connection.service.ts`,
  `desktop/src/shared/dto/text-provider.dto.ts`,
  `desktop/src/renderer/components/molecules/ModelCatalogFacts.tsx`

## Контекст

Характеристики моделей приходят от самих провайдеров, и они неравноценны:

- OpenRouter отдаёт всё: `context_length`, `max_completion_tokens`, цены,
  `supported_parameters`, модальности;
- Mistral отдаёт `max_context_length` и флаги возможностей, но не отдаёт цены
  и лимит ответа;
- Ollama (`/api/tags` + `/api/show`) не отдаёт ни длину контекста, ни цены —
  только размер файла, квантизацию и список capabilities.

Это не косметика. `contextLength` — вход бюджета контекста
(`context-budget.ts`). Когда его нет, `resolveContextBudget` подставляет
`DEFAULT_CONTEXT_LENGTH = 32 768`, то есть каждая локальная модель считается
32-килотокенной независимо от реального окна (у qwen3 и gpt-oss оно кратно
больше). Следствия:

- компактизация запускается раньше, чем нужно, и теряет контекст без причины;
- `ModelFailover` сортирует цепочку по `contextLength`, а у моделей Ollama он
  равен нулю (`modelInfo(...).contextLength ?? 0`) — «более широкая модель»
  при `context_overflow` среди них не находится никогда;
- `pickSummarizerModel` специально предпочитает локальную модель, «чей бюджет
  вмещает весь диапазон», но с бюджетом по умолчанию почти всегда отказывается
  от неё и уходит в платную модель — ровно то, чего эта эвристика избегает.

models.dev публикует открытый каталог (`https://models.dev/api.json`,
213 провайдеров, ~7500 моделей) ровно с этими полями: `limit.context`,
`limit.output`, `cost`, `tool_call`, `structured_output`, `reasoning`,
`modalities`, `knowledge`, `open_weights`.

## Решение

Каталог используется как **источник, дополняющий пробелы**, а не как источник
списка моделей. Список моделей по-прежнему даёт провайдер: запускается только
то, что провайдер реально обслуживает.

`ModelsDevCatalog` скачивает `api.json` целиком (4,4 МБ, 440 КБ в gzip;
покусочного эндпоинта у сервиса нет), кэширует его в
`userData/models-dev-catalog.json` вместе с ETag и обновляет не чаще раза в
сутки, условным запросом. Сеть недоступна — берётся устаревший кэш; кэша нет —
каталог пуст. Ни одна ветка не бросает: обогащение не может сломать проверку
подключения.

`ProviderConnectionService.testConnection` после ответа провайдера
подмешивает найденные записи в `details`. Правила слияния:

- поля заполняются только если провайдер их **не** прислал (`undefined`);
- цены не подставляются моделям Ollama — локальный запуск ничего не стоит,
  и цена чужого хостинга той же модели ввела бы в заблуждение;
- возможности не пишутся в `supportsTools`/`supportsVision`/…: эти поля —
  канал ручных переопределений пользователя (`pickCapabilityOverrides`).
  Каталог пишет в `supportedParameters`/`inputModalities`, из которых
  `resolveModelCapabilities` выводит возможности, и только когда провайдер не
  прислал свой список;
- запись помечается `catalogSource: "models.dev"` — интерфейс показывает
  происхождение данных и даёт фильтр «Только открытые веса».

Сопоставление идентификаторов двухступенчатое: сначала точное совпадение в
каталоге того же провайдера (`openrouter`, `mistral`, `ollama-cloud`), затем —
только для Ollama — поиск по всем моделям с открытыми весами. Ключи
нормализуются: снимается суффикс варианта OpenRouter (`:free`, `:nitro`),
тег Ollama (`qwen3:8b` → `qwen3`), вставляется дефис на границе «буква→цифра»
(`gemma3:27b` → `gemma-3-27b`), отбрасываются `instruct`, `it`, `hf`,
`latest` и квантизации. На реальном каталоге это даёт 6/6 для OpenRouter,
5/5 для Mistral и 8/9 для типового набора локальных моделей Ollama.

## Последствия

- Локальные модели получают настоящую длину контекста: бюджет, компактизация
  и выбор суммаризатора начинают работать так, как задумано.
- Mistral получает цены и лимит ответа, которых у него в API нет.
- Появляется зависимость от внешнего сервиса — мягкая: офлайн приложение
  работает как раньше, просто без дополнений.
- Поиск по открытым весам для Ollama даёт характеристики **чужого** хостинга
  той же модели: длина контекста может отличаться от того, что реально
  сконфигурировано в Modelfile. Это компромисс в пользу «примерно верно»
  против «заведомо неверных 32 768», и он виден пользователю по метке
  `models.dev` на карточке.
- Кэш нужно инвалидировать при смене формата каталога — схема разбирается
  лениво, неизвестные поля игнорируются.

## Альтернативы

**Захардкодить таблицу характеристик в репозитории.** Отвергнуто: таблица
устаревает на каждом релизе моделей, а поддерживать её вручную —
та самая работа, которую models.dev уже делает публично.

**Брать из каталога сам список моделей и показывать его как витрину.**
Отвергнуто: приложение может запустить только то, что отдаёт подключённый
провайдер. Список из 7500 моделей, из которых запускается сотня, — витрина,
которая обещает больше, чем система умеет.

**Спрашивать длину контекста у пользователя вручную.** Отвергнуто: значение
неочевидно, ошибка в нём проявляется не сразу, а как деградация качества
диалога после компактизации.

**Ходить в models.dev при каждой проверке подключения.** Отвергнуто: 4,4 МБ на
каждое нажатие «Проверить», при том что каталог меняется раз в дни. Суточный
TTL плюс ETag дают то же самое почти бесплатно.

**Отдельный IPC-канал и экран управления каталогом.** Отвергнуто пока: у
обогащения нет настроек, которыми имело бы смысл управлять, а обновление
привязано к синхронизации провайдера — жесту, который пользователь уже делает.
